# 서버 QA 파트 리딩 (Server QA Part Lead)

> 포트폴리오 **02. 서버 QA 파트 리딩 (LEAD)** 참고 자료

서버 정기배포 QA를 리딩하면서 진행한 **일정·이슈 관리, 테스트케이스 설계, 결과 리포팅** 과정을 정리한 저장소입니다.
코드 없이 실제 업무 산출물(샘플 이미지)로 구성되어 있습니다.

---

## 📌 업무 개요

| 항목 | 내용 |
| --- | --- |
| 역할 | 서버 QA 파트 리드 |
| 대상 | 서버 정기배포 (월 단위 Sprint) |
| 주요 업무 | QA 일감 배분, 진행 현황 모니터링, 테스트케이스 설계·리뷰, API 검증, 결과 리포트 작성 |
| 사용 도구 | JIRA (Dashboard / Filter), ONE tests (TC 관리), Postman (API 검증), Excel (지표 분석) |

### 업무 흐름

```
정기배포 일감 등록 (JIRA)
   → QA 담당자 배분 및 Dashboard 모니터링
   → 일감별 테스트케이스 설계 / API 검증
   → 결함 등록 및 확정 처리 추적
   → 정기배포 결과 Report 작성 및 공유
```

## 1. 서버 정기배포 JIRA Dashboard

<img width="461" height="286" alt="서버정기배포 Dashboard" src="https://github.com/user-attachments/assets/f16b6224-686d-4e7b-bda0-2d438c10e389" />

정기배포 일감을 한눈에 관리하기 위해 JIRA Filter 기반 Dashboard를 구성했습니다.

- **일감 상태 현황** : 배포 대상 일감의 상태(진행/완료 등)를 실시간으로 확인
- **QA 담당자별 배분** : 담당자별 Issue Count를 파이 차트로 시각화하여 업무 편중 여부 확인
- **보고자(Reporter)별 현황** : 개발 파트별 요청 일감 규모 파악
- **우선순위별 진행률** : Priority 기준 처리 진척도 확인
- **일감 목록** : 배포 대상 일감 리스트와 상태를 함께 관리

> 파트 리드로서 Dashboard를 통해 매일 진행 상황을 점검하고, 지연 일감 및 리소스 편중을 조기에 조율했습니다.

## 2. 정기배포 JIRA 일감 기반 테스트케이스

<img width="855" height="255" alt="정기배포 Jira 일감 테스트케이스" src="https://github.com/user-attachments/assets/80886267-2b1b-4f00-9e73-308932d74386" />

JIRA 요구사항(일감) 단위로 테스트케이스를 설계하고 ONE tests로 검증 결과를 연결해 관리했습니다.

- **요구사항 ID ↔ 테스트케이스 ID 매핑**으로 추적성(Traceability) 확보
- **품질지표 / 중요도(상·중·하)** 를 TC마다 지정하여 우선순위 기반 검증
- **사전조건** 을 통신사(SKT / KT) × 상품 유형(게임 / 앱) × 데이터 조건으로 조합하여 커버리지 확보
- **API 단위 절차** : API 호출 → Response Result 확인 → 응답 필드(binaryInfo 등) 검증
- **ONE tests 검증 결과 링크** 로 증적(Evidence) 관리 및 Pass/Fail 결과 기록

> 예시) `[CCS] Android 14 앱 설치 사전 동의 프로세스 반영` — 상품 리스트 조회 API의 `applicationLabel` 응답 여부 검증

## 3. 정기배포 결과 Report

<img width="1367" height="792" alt="정기배포 Report" src="https://github.com/user-attachments/assets/e4963efd-1dd5-48f4-a310-7a838018c434" />

배포 완료 후 검증 결과와 품질 지표를 정리하여 유관 부서에 공유했습니다.

### QA 환경 검증 결과 (JIRA 일감 기준)

| 구분 | Total | Pass | Fail | 검증대상제외 |
| --- | :---: | :---: | :---: | :---: |
| SAC | 16 | 6 | 0 | 10 |
| Tenant | 27 | 24 | 0 | 3 |
| **총** | **43** | **30** | **0** | **13** |

- 검증대상제외 13건 : 배치 및 개발자 자체 검증 항목
- 검증 완료 후 결함 **30건 모두 확정완료** 처리 (정상동작 8건 제외 시 실제 결함 22건)

### 품질 지표 분석

- **개발파트별 초기 Pass율** : 파트별 구현 일감 대비 Fail 발생 건수를 분석 (평균 **79.1%**)
- **정기배포 개발완료율 추이** : D-10 **48.8%** → D-1 **100%** 로 일정별 진척도 추적
- **파트별 개발완료율** : 파트별 지연 구간을 파악하여 일정 리스크를 사전에 공유

> 단순 Pass/Fail 결과뿐 아니라 **초기 Pass율·개발완료율** 지표를 함께 제공하여, 개발 파트의 품질 개선과 일정 관리에 활용될 수 있도록 했습니다.
